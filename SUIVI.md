5. **Le jeu complet, API et base comprises, sur GitHub, et sur InfinityFree aussi** — « on me dit que github pour les projet open source ouvert, on peut les heberger chez eu, db comprise, integre ce projet ful api et db inclu dans github » puis « tu fera vivre sur les 2 site, on garde infinityfree quand meme » puis « pour integrer le projet en full qui foncitonne sur github tu peu t'inspirer de supabase ici https://github.com/ITGourmand/Translator/tree/main/supabase » (17/11).

   Compris : le projet vivrait sur deux sites, InfinityFree (PHP et MariaDB, déjà publié) et GitHub (le site statique de la vitrine, avec un serveur chez Supabase, déployé depuis GitHub). Deux façons, à choisir (question 1) ; rien n'est codé pour ce point avant ta réponse.

## Questions en suspens

1. **GitHub : quelle voie ?** (A) Le site GitHub appelle l'API qui est déjà sur InfinityFree : un seul serveur et une seule base, le même monde sur les deux sites, peu de travail (autoriser l'autre site dans l'API, régler le cookie de session, et vérifier que la protection anti-robot d'InfinityFree laisse passer les appels d'un autre site, ce qui n'est pas sûr). (B) Un second serveur chez Supabase, comme dans ton exemple : tout le serveur est à réécrire en TypeScript et en SQL Postgres (comptes, monde, base, atelier, missions, alertes, résultats), un travail de plusieurs jours, avec deux serveurs et deux bases séparées à faire évoluer ensemble ; il te faut créer le compte et le projet Supabase toi-même (je ne crée pas de compte), puis poser ses clés comme secrets du dépôt. Je recommande A d'abord ; B plus tard si A est bloquée. L'adresse du site est maintenant connue (`ww2.gamer.free`) : je peux tester dans le navigateur si l'anti-robot laisse passer les appels d'un autre site.
2. **Les images pour la carte** : `carte-france.png` (muette, sans texte) et les états de camp à faire générer ; les missions choisies n'ont pas d'écran sans elles.
3. **Plusieurs bases : la bataille et le guide.** La bataille (8 avions ennemis abattus pour gagner) est aujourd'hui rattachée à la base unique, et le guide aussi. Avec plusieurs bases : (A) la bataille se compte pour le joueur (les abattus de toutes ses bases) et le guide ne sert que la première base ; (B) chaque base a sa propre bataille. Je recommande A.
4. **Attaque au sol : des véhicules à épargner ?** La vue en diagonale (celle de Wings, d'après ta feuille) et le tir automatique sont faits. Reste : des véhicules à épargner (Croix-Rouge, comme Wings), avec une pénalité, ou aucun au début (ma proposition) ?
5. **La scène 3D, affichage permanent de la base ?** Pour que les avions garés soient des modèles 3D (point 12), la scène 3D doit être là en permanence, pas seulement pendant un décollage. (A) Oui : la scène 3D devient l'affichage de la base, la carte à plat ne sert plus que de secours là où WebGL manque ; coût à surveiller : chaque avion numéroté a sa texture de 16 Mo (point du cahier sur les numéros de queue), donc six avions garés font environ 96 Mo, lourd pour un téléphone (point 10) ; je les ferais partager une seule texture de base avec le numéro posé à part. (B) Non : seuls les avions qui bougent sont en 3D, comme aujourd'hui. Je recommande A, avec le partage de texture pour le téléphone.
